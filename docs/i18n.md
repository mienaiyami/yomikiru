# Internationalization (i18n)

Yomikiru localizes both the React renderer and Electron main (menus, tray, native dialogs) with **i18next**.

## Stack

| Process | Setup |
| --- | --- |
| Renderer | `i18next` + `react-i18next`, `useSuspense: false`, bundled English resources seeded at init (all namespaces); packs via `addResourceBundle`. Do not pin `supportedLngs` to `["en"]` (blocks pack locales). |
| Main | Separate `i18next` instance; init with `cloneBundledI18nResources()` (i18next keeps `resources` by reference and mutates them on pack merge). Clearing a pack reseeds builtins from clones and re-adds empty bundles for pack-only locales so `ns` stays registered. |
| Packs | Flat zip under `{userData}/i18n-packs/<id>/` (one locale per pack), install via existing `cross-zip` |

## Language source setting

Stored in **main settings** as `languageSourceId` (default `builtin:en`).

- Builtin: `builtin:en` (more builtins may ship later)
- Pack: `pack:<packId>`

Change language only through IPC `i18n:setSource` (not `mainSettings:update`) so main i18n, application menu, and all windows stay in sync.

Settings UI: **Settings → Language** (General, after Theme). Dropdown shows `locale - name`.

## Pack format (one locale per pack)

```text
pack.json
common.json
dialogs.json
usage.json
...
```

`pack.json` fields: `id`, `name`, `locale`, `version`, `namespaces`.

Rules:

- No nested `locales/` directory
- Only `pack.json` + allowlisted `<ns>.json` files
- Partial packs deep-merge over bundled English (`fallbackLng: "en"`)

## Catalogs

Bundled locales live in `src/common/i18n/locales/<locale>/*.json`.

Namespaces: `common`, `dialogs`, `menu`, `settings`, `home`, `reader`, `anilist`, `electron`, `usage`.

Prefer shared keys in `common` / `dialogs` when the same meaning is reused.

### Adding a builtin locale

1. Add `src/common/i18n/locales/<locale>/*.json` (partial namespaces OK; missing keys fall back to `en`).
2. Import them in a small `bundledXx.ts` module (see `bundledEn.ts`).
3. Append one row to `BUILTIN_LOCALES` in [`builtins.ts`](../src/common/i18n/builtins.ts).

Picker entries, init `resources`, and builtin export all derive from that registry — no other call sites.

## Usage tab (React skeleton + structured keys)

Settings → Usage is long-form help. It ships as the **`usage`** namespace (`usage.json`), not React locale modules.

The layout (lists, nesting, deep-link ids, `ul.fileExample`, platform branches) is a fixed React skeleton in `Usage.tsx`; only the prose lives in `usage.json` as structured keys grouped by section. There is no `html` blob and no `dangerouslySetInnerHTML`.

| Piece | Role |
| --- | --- |
| [`locales/en/usage.json`](../src/common/i18n/locales/en/usage.json) | Bundled English; structured keys per section (`language`, `reader`, `readerPresets`, ...), nested objects, some with `<code>` / `<bold>` / `<italic>` / `<link>` markup for `Trans` |
| [`Usage.tsx`](../src/renderer/features/settings/components/Usage.tsx) | Fixed JSX skeleton; `useTranslation("usage")` for plain copy, `Trans` for mid-sentence markup, `SettingsLink` for in-app jumps, live shortcuts / paths as interpolation values |
| [`usageKeys.ts`](../src/renderer/features/settings/utils/usageKeys.ts) | `keysFor(shortcuts, command)` joins a command's keys; `PRESET_SLOT_COMMANDS` lists slots 1-5 |

Pack authors include `usage` in `namespaces` and ship `usage.json` to replace/overlay the guide. They translate values only; the skeleton and markup tag names stay the same.

### Conventions

- Deep-link targets keep stable `id`s on the JSX element (e.g. `settings-usage-anilist`)
- In-app settings jumps use the local `SettingsLink` (`tab` is a Settings tab key, `target` a CSS selector); as a `Trans` `<link>` component or a direct child
- Prefer `<b>{t("section.title")}</b> {t("section.body")}` when bold is only a leading label; use `Trans` when markup or a link sits mid-sentence
- Markup tag names in values map to `Trans` `components`: `<bold>` -> `<b>`, `<italic>` -> `<i>`, `<code>` -> `<code>`, `<link>` -> `<SettingsLink>`
- Live shortcuts / host paths are `Trans` interpolation values (e.g. `<code>{{down}}</code>` filled by `keysFor(shortcuts, "listDown")`, `{{sep}}` from `window.path.sep`, `{{path}}` from the example manga path)
- Preset slots 1-5 render in JSX from `PRESET_SLOT_COMMANDS`
- OS-only bullets stay in JSX behind `process.platform === "win32"`
- Hardcoded example names (`One Piece`, `001.png`, etc.) live in JSX and are not translated; only reused strings like `use "Open" here` are keyed

Do not reintroduce an `html` blob or push hundreds of sentence-level Usage keys into other namespaces; keep the guide in the `usage` namespace.
